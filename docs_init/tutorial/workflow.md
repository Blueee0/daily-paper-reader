# 推荐与精读报告

在「设置 → 密钥配置」填写 API Key、Base URL 与模型名称。支持 OpenAI Chat Completions 兼容接口；原生 Claude / Gemini 协议需要对应兼容网关。Base URL 可以填写平台根地址、带 `/v1` 的地址或完整 `/chat/completions` 地址。模型名按平台要求原样填写。

默认由工作流和聊天共用一套配置。「高级设置」可单独覆盖聊天配置。浏览器连接测试只验证当前网络；保存时还会同步 GitHub Secrets，下一次工作流才使用新配置。同步失败时不要启动任务，重新保存以补齐；不要把 API Key 写入公开 config.yaml。

## 查看运行进度

首页顶部显示当前日常工作流状态，「查看执行过程」可看排队、召回、排序、模型评分、文档生成与发布的阶段及耗时。关闭页面不取消任务；重新打开后可从最近运行恢复查看。

“日报生成成功”“产物已提交”和“网站已核验更新”是不同状态。接口限流或网络失败会显示“暂不可确认”，不代表任务失败。长时间无更新先打开 GitHub Actions 查看，不要重复提交。

## 配置自动执行

日常管理的「自动执行计划」打开当前仓库的真实计划。可选择时区、时间、每天、周一至周五或指定星期。周一至周五不判断节假日和调休；所有启用的日常方向共用计划。保存需要 GitHub Token 对 Contents / Workflows 的写权限。

新保存的计划支持 IANA 时区（默认 Asia/Shanghai）。旧 UTC 计划可读入迁移。高级设置可增加随机等待，默认零分钟；GitHub 的排队仍可能造成延迟，预计时间不是精确承诺。保存后会读回仓库验证，发生并发修改时请重新打开再编辑。

## 精读报告与下载

新精读论文自动使用仓库根目录的 `read_paper_prompt.md`，基于论文全文和联网文献证据生成十二节报告。Semantic Scholar 的独立 Key 可在密钥配置填写；Crossref 核验 DOI。检索最多三条查询、十二篇证据，报告会区分原文事实、摘要证据和推测，不保证检索完整或设想具有创新性。

阅读页提供「下载本页 Markdown」与「下载研究报告 .md」。下载读取已保存文件，不调用模型。旧精读页保留原报告；「补生成精读报告」可选择一至二十篇已有论文，只补内容，不重做召回与评分。查看所选数量后再提交，模型按实际用量计费。

全文缺失、报告截断或引用校验失败时不算完成，也不会覆盖原有完整报告。成功结果绑定论文版本、全文、prompt、模型和文献证据缓存；重复运行会复用。缓存不是永久保留承诺，已发布的报告及校验信息仍可用于续跑。速读论文保持原有速览结构。
